lua api

Scripts live in Documents\<user>\scripts\*.lua and load from the scripts tab.

Each script gets its own Lua state, so scripts cannot see or corrupt each other's globals. Every call into script code is protected — a script that raises is logged and unloaded, because a handler that throws once on a per-frame path throws every frame.

events — and when each is valid

eventargfires
paint—Once per rendered frame, above the game, below the menu.
pre_movecmdTop of the tick, before the strafer.
in_movecmdAfter prediction, before the aimbot.
post_movecmdAfter the movement fix and final re-prediction.
Why the three move events sit where they do — it changes what your edits actually do.

pre_move runs before StartMove snapshots the cmd, and the strafer reads those snapshots rather than the live cmd. Input edits must happen here to be seen by it. send_packet is not yet meaningful.

in_move is the only point where weapon:get_inaccuracy() describes the shot about to be taken. Skipped while the doubletap key is held, same as the aimbot.

post_move is the last point cmd can be edited coherently. Inaccuracy read here reflects post-fire penalty state — next tick's starting value, not what the shot used.

Draw, left-aligned or centred.

Text with a coloured halo behind it.
render.fonts.menu · menu_bold · menu_tab
The menu's own faces, so you can match the UI without building anything.
font_flags — none, antialias, dropshadow, outline. font_aa — default, none, standard, cleartype.

These are independent on purpose. font_aa threads straight to CreateFont's quality argument; font_flags.antialias only derives it when font_aa is default. Raster faces need font_aa.none explicitly or they turn to mush.

Dropshadow and outline are baked into the atlas at creation, so they live on the font, not the draw call.

props — and the set_prop gate

e:get_prop( name ) always allowed
Typed by the RecvProp; nil if unknown. Resolved by name against the entity's own recv table, so it is exact and never force-flattens every class.
e:set_prop( name, value ) gated
Returns true/false and refuses loudly, with the reason in console.
e:get_prop_address( name ) · e:address( )
Raw address, for ffi. Inert without ffi, so it needs no gate of its own.
refusedwhy
non-local entitiesOverwritten by the next server update anyway; only corrupts your own lagcomp and resolver state in between.
animation fieldssoggybot's anim pipeline assumes it is the only writer.
predicted fieldsRestored every re-prediction — the write is silently reverted, or corrupts the baseline.
Predicted fields are detected, not listed. The gate reads the entity's own prediction datamap, so it cannot rot as the game changes. If you genuinely mean it, use get_prop_address + ffi.

weapon

w:get_item_index( ) · w:get_ammo( ) · w:get_next_attack( )
Definition index, clip, next-attack time.

Mode selects between primary and _alt values. Max speed follows it.

Time between shots for the current mode.
w:get_inaccuracy( ) · w:get_spread( ) in_move only
Returns nil for anything that is not the local player's active shootable weapon. These are predicted globals describing that weapon only — a number for anyone else's would be a confident lie.

weapon data — w:get_wpn_data()

The whole WeaponInfo as a table. Static per weapon definition, so it carries none of the freshness caveats above — but it builds a fresh table each call, so hoist it out of hot loops. Returns nil for a tick around skin-changer definition swaps.

cycletime is not recovery time. cycletime is time between shots — fire rate. recovery_time_* is how fast inaccuracy decays back down after firing. "Recovers after one shot" is the second one.

ffi

Off by default. Enable allow unsafe scripts in the scripts tab.

local ffi = require( "ffi" )
local addr = me:get_prop_address( "m_flFlashDuration" )
ffi.cast( "float*", addr )[ 0 ] = 0
FFI gives a script full access to the process — it can do anything the cheat can. Only enable it for scripts you wrote or trust. Once it is on, every safety gate in this document is advisory: a script can write the memory directly.
You still never hardcode an offset. That is the point of entity.get_offset and e:get_prop_address — escaping the safe path shouldn't also mean giving up build independence, since hardcoded offsets are what actually rot on a game update.

gotchas

validity windows
get_inaccuracy, get_spread and get_mode are predicted — only trustworthy from in_move onward, never from paint. get_wpn_data is static and always safe.
one callback slot per element
ui.set_callback called twice on the same handle replaces the first. Do the work in one function.
handles are never recycled
A handle whose element was destroyed resolves to nil forever after, so a stale reference is inert rather than dangerous.
errors unload the script
Deliberate — a broken handler on a per-frame path would otherwise spam at framerate. The unload is logged.
column 0 vs column 1
On the shared manager page, column 0 belongs to the script manager — use column 1. On your own subtab, both are yours.
