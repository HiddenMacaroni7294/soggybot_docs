start

overview

Put .lua files in Documents\<user>\scripts\ and load them from the scripts tab.

Every script runs in its own sandbox, so scripts can’t break each other. If a script errors it gets unloaded and the error is printed to console.

Where things live. ui makes menu controls, render draws, entity reads the game, callbacks hooks events, enums holds the lookup tables. Anything unavailable comes back as nil rather than erroring.
-- a minimal script
local enabled = ui.checkbox( "scripts", 1, "my script", true )

callbacks.add( "paint", function( )
    if not enabled:get( ) then return end
    render.text( 10, 10, 255, 178, 0, 255, "hello" )
end )

callbacks

Hook an event and your function runs whenever it fires. You can add as many handlers as you like, and every script’s handlers are independent.

callbacks.add( event, fn )
Register a handler. Returns false and logs if the event name doesn’t exist.
callbacks.remove( event )
Remove every handler your script added for that event.

events

move events

Three moments in the same tick, each handed the same cmd object.

pre_move

function( cmd )

The start of a tick, before the cheat has touched anything. Change movement or buttons here and the rest of the cheat sees your version.

-- auto-crouch whenever we jump
callbacks.add( "pre_move", function( cmd )
    if cmd:has_button( enums.buttons.IN_JUMP ) then
        cmd:add_button( enums.buttons.IN_DUCK )
    end
end )

in_move

function( cmd )

The middle of a tick. Everything about your player and weapon is up to date, which makes it the right place to read state and decide what to do.

Doesn’t fire while the doubletap key is held.

-- stop moving while our accuracy is bad
callbacks.add( "in_move", function( cmd )
    local me = entity.get_local_player( )
    local w  = me and me:get_weapon( )
    if not w then return end

    local inacc = w:get_inaccuracy( )
    if inacc and inacc > 0.05 then
        cmd:set_forwardmove( 0 )
        cmd:set_sidemove( 0 )
    end
end )

post_move

function( cmd )

The end of a tick, after the cheat has finished. Last chance to change anything before it goes to the server, and the only place get_send_packet is final.

-- how many ticks actually reached the server
local sent, choked = 0, 0

callbacks.add( "post_move", function( cmd )
    if cmd:get_send_packet( ) then sent = sent + 1
    else choked = choked + 1 end
end )
Order matters for predicted values. get_inaccuracy, get_spread, get_mode and can_fire are predicted, so when you read them changes what you get:

· pre_move — one tick behind
· in_move — current, and what the aimbot is about to act on
· post_move — already rolled forward to next tick

events

paint & esp

paint

function( )

Once per frame while you’re in a game, after the world is drawn but before the menu. Everything in render only works from here.

callbacks.add( "paint", function( )
    local w, h = render.screen_size( )
    render.text( w - 120, 10, 255, 178, 0, 255, "soggybot" )
end )

player_esp

function( ctx )

Once for every player whose ESP is on screen, after all the built-in elements have drawn — so anything you draw lands on top. Players who are dormant, faded out or off screen never reach it, so you don’t need to filter.

Handed an esp object.

callbacks.add( "player_esp", function( ctx )
    local p = ctx:get_player( )
    local x, y, w, h = ctx:get_bbox( )

    -- flags append below the built-in ones, same column and styling
    if p:get_prop( "m_bHasDefuser" ) == 1 then
        ctx:add_flag( "kit", 120, 220, 120 )
    end

    -- drawn on top of the built-in box
    render.rect( x - 2, y - 2, w + 4, h + 4, 255, 178, 0, 90 )
end )

events

aimbot events

All three are handed a shot object. aim_fire fires immediately; the other two land later, when the server answers.

aim_fire

function( shot )

The aimbot pulled the trigger. Everything about the shot is captured at this moment, including what it aimed at.

-- a fired-shot log
callbacks.add( "aim_fire", function( s )
    local t = s:get_target( )

    client.log( string.format( "fire -> %s %s | hc %.0f%% | dmg %.0f",
        t and t:get_name( 12 ) or "?",
        enums.hitbox[ s:get_hitbox( ) ] or "?",
        s:get_hitchance( ),
        s:get_aim_damage( ) ) )
end )

aim_hit

function( shot )

The server confirmed the shot landed. This is the only event where the get_hurt_* values mean anything.

-- aimed vs actually hit. the two disagreeing is a resolver miss
callbacks.add( "aim_hit", function( s )
    local aimed = enums.hitgroup[ s:get_hitgroup( ) ]   or "?"
    local hit   = enums.hitgroup[ s:get_hurt_group( ) ] or "?"

    if aimed ~= hit then
        client.color_log( 255, 178, 0,
            string.format( "aimed %s but hit %s", aimed, hit ) )
    end
end )

aim_miss

function( shot )

The shot didn’t land. get_reason() is one of spread, resolver or unknown.

-- tally misses by reason, and draw the tally
local misses, total = { }, 0

callbacks.add( "aim_miss", function( s )
    local why = s:get_reason( )

    misses[ why ] = ( misses[ why ] or 0 ) + 1
    total = total + 1

    client.color_log( 235, 80, 80,
        string.format( "miss (%s) aimed %s at %.0f%%",
            why,
            enums.hitbox[ s:get_hitbox( ) ] or "?",
            s:get_hitchance( ) ) )
end )

callbacks.add( "paint", function( )
    if total == 0 then return end

    local y = 300
    render.text( 12, y, 255, 255, 255, 255, "misses: " .. total )

    for why, n in pairs( misses ) do
        y = y + 14
        render.text( 20, y, 235, 80, 80, 255,
            string.format( "%-9s %d (%.0f%%)", why, n, n / total * 100 ) )
    end
end )
Resetting between rounds pairs well with these — hook round_start and clear your tally there.
callbacks.add( "round_start", function( )
    misses, total = { }, 0
end )

events

game events

Registered by name, same as anything else.

any game event

function( event )

Any event the game itself has — player_hurt, player_death, weapon_fire, round_start, item_pickup, and the rest. You don’t need the cheat to already listen for it; asking subscribes to it.

Handed an event object.

-- damage we dealt, with the hitgroup named
callbacks.add( "player_hurt", function( e )
    local victim   = e:get_player( "userid" )
    local attacker = e:get_player( "attacker" )
    local me       = entity.get_local_player( )

    if not me or not attacker or attacker:index( ) ~= me:index( ) then
        return
    end

    client.color_log( 255, 178, 0,
        string.format( "hit %s in the %s for %d (%d left)",
            victim and victim:get_name( 12 ) or "?",
            enums.hitgroup[ e:get_int( "hitgroup" ) ] or "?",
            e:get_int( "dmg_health" ),
            e:get_int( "health" ) ) )
end )

a kill feed

callbacks.add( "player_death", function( e )
    local victim   = e:get_player( "userid" )
    local attacker = e:get_player( "attacker" )

    client.log( string.format( "%s killed %s with %s%s",
        attacker and attacker:get_name( 12 ) or "?",
        victim   and victim:get_name( 12 )   or "?",
        e:get_string( "weapon" ),
        e:get_bool( "headshot" ) and " (hs)" or "" ) )
end )
A name the game doesn’t have returns false and logs “no such event”, so a typo’d event tells you instead of silently never firing.

events

world events

net_update_start

function( )

Before the game applies a network update.

net_update_end

function( )

After the game has applied a network update — entity positions and properties are fresh here.

callbacks.add( "net_update_end", function( )
    for _, p in ipairs( entity.get_players( true ) ) do
        if not p:is_dormant( ) then
            -- freshest data you can get for enemies
        end
    end
end )

level_init

function( )

A map finished loading. Good place to reset per-map state.

local seen = { }

callbacks.add( "level_init", function( )
    seen = { }
end )

level_shutdown

function( )

Leaving a map.

These are per map, not per session. level_init and level_shutdown fire on every map change and every reconnect, not once when you start the game.

The two net_update events are also skipped on a full update, which happens right after a map load.

objects

cmd

Handed to the move events. It’s how you change what gets sent to the server.

cmd:get_yaw( ) · cmd:set_yaw( v )
Also pitch and roll.
cmd:get_forwardmove( ) · cmd:set_forwardmove( v )
Also sidemove and upmove.
cmd:get_send_packet( ) · cmd:set_send_packet( bool )
Whether this tick is sent to the server.
cmd:get_weaponselect( ) · cmd:set_weaponselect( v )
Weapon switch.
cmd:add_button( bit ) · cmd:strip_button( bit ) · cmd:has_button( bit )
Add, remove or test a button. See enums.
cmd:get_buttons( ) · cmd:get_command_number( ) · cmd:get_tick( ) · cmd:get_random_seed( )read only
Changing these would desync you from the server.
cmd:quick_stop( [slide] ) → bool
Counter-strafe to a stop — the same routine the cheat’s own auto stop uses. Pass true to stop at the weapon’s accurate walking speed instead of a dead halt. Returns false if it was refused.
quick_stop works in pre_move and in_move, not post_move. By post_move the movement fix has already run, so anything written then is in the wrong frame of reference and nothing corrects it. It also returns false when you’re dead or the command isn’t the one the cheat is working on.
IN_ATTACK is handled by the cheat. You can’t remove it — the aimbot already decided. You can add it, but only when client.can_fire() is true. Both calls return false if the attack bit was ignored.
Only use cmd inside the callback that gave it to you. Don’t save it in a variable for later.

objects

shot

Handed to the aimbot events. Everything is captured when the shot is fired, so it still describes that shot when it resolves a moment later.

shot:get_target( ) → entity | nil
Who we shot at.
shot:get_hitbox( ) · shot:get_hitgroup( )
What we aimed at. Name them with enums.hitbox / enums.hitgroup.
shot:get_hitchance( ) · shot:get_point_hitchance( )
The final gate value, and the aimed point’s own. The final one is 0 whenever hitchance is turned off in the menu — the cheat never computes it. get_point_hitchance() is the one you usually want.
shot:get_aim_damage( ) · shot:get_avg_damage( )
Predicted damage, and the mean across the spread seeds that connected.
shot:is_lethal( ) · shot:is_penetrated( ) · shot:get_overlap( )
Whether the point would kill, went through a wall, and its safepoint score (-1 = not scored).
shot:get_hurt_group( ) · shot:get_hurt_damage( ) · shot:get_hurt_health( )aim_hit
What the server said. Only meaningful in aim_hit.
shot:get_reason( )aim_miss
Why it missed: spread, resolver or unknown. Empty otherwise.
shot:get_damage( ) · shot:get_time( ) · shot:get_latency( ) · shot:get_weapon_id( )
Shot damage, when it was fired, your latency at the time, and the weapon.
There are two hitgroups on purpose. get_hitgroup() is what the aimbot aimed at; get_hurt_group() is what the server says was hit. Them disagreeing is exactly what a resolver miss looks like.

esp

Handed to player_esp, once per player per frame.

ctx:get_player( ) → entity
The player being drawn.
ctx:get_bbox( ) → x, y, w, h
The box on screen. Always valid — a player whose box can’t be projected never reaches the callback.

game event

Handed to game events.

e:get_name( )
The event’s name.
e:get_int( key ) · e:get_float( key ) · e:get_bool( key ) · e:get_string( key )
Read a field by name. Keys are the game’s own — userid, dmg_health, weapon…

objects

ui item

What every ui constructor returns. A control that has been destroyed stays safe — its methods just do nothing.

item:get( )
The control’s value, typed by what it actually is: boolean for a checkbox, number for a slider or combobox, live on/off for a hotkey, {r,g,b,a} for a colour picker, an array of indices for a multiselect.
item:set( value )
Write it back, same types.
item:set_visible( bool )
Show or hide. Re-read every frame, so flip it freely.
item:set_callback( fn )
Runs when the value changes. One per control — setting it again replaces the old one.
item:set_subtab( page )
Move it onto a page from ui.subtab.
item:name( ) · item:valid( )
Its label, and whether it still exists.
local mode  = ui.combobox( "scripts", 1, "mode", "off", "low", "high" )
local power = ui.slider( "scripts", 1, "power", 0, 100, 50 )

-- hide the slider unless a mode is picked
mode:set_callback( function( )
    power:set_visible( mode:get( ) ~= 0 )
end )
Values save automatically with the config, and load correctly even if the config was loaded before your script was.

animation layers

local layers = p:get_animlayers( )

for i = 0, 12 do
    local l = layers[ i ]
    if l and l.weight > 0 then
        print( enums.animlayer[ i ], l.sequence, l.weight, l.cycle )
    end
end
Each layer has sequence, cycle, prev_cycle, weight, weight_delta, playback_rate, anim_time, fade_out_time and order.
Your own layers come from what the cheat drove this tick, not from the entity’s raw overlay — so a script and the cheat agree on them. Everyone else’s come from their overlay.
get_net_layers is delayed, and that is the point. For yourself it is the set the server is working from, which lags what you are actually doing by your latency — so comparing it against get_animlayers shows you the gap between what you are doing and what the server thinks you are doing. For anyone else their overlay already is the networked data, so the two return the same thing.

It is ground truth in the sense that the server acts on it; it is not current.

animstate

local a = p:get_animstate( )

-- eye yaw is where they look, foot yaw is where the body points.
-- the gap between them is the desync a resolver is solving.
print( a.eye_yaw, a.foot_yaw, a.duck_amount, a.on_ground )
Grouped as angles (eye_yaw, foot_yaw, move_yaw, time_to_align), movement (velocity, speed, run_fraction, duration_moving), stance (duck_amount), air (on_ground, landing, duration_in_air), ladder and a few flags. Read only — writing animstate is the cheat’s job.

weapon data

w:get_wpn_data() returns a table of everything the game knows about that weapon. These never change, so read once and keep it.

world

trace

Ask the game what’s actually there — line of sight, cover, surfaces, and how much damage a bullet would still be carrying when it arrives.

trace.line( x1, y1, z1, x2, y2, z2, [skip], [mask] ) → table | nil
Fire a ray. skip is an entity to ignore — it defaults to you, so a trace from your own eyes doesn’t just hit your own hitboxes. mask defaults to enums.mask.shot.
trace.hull( x1, y1, z1, x2, y2, z2, mins, maxs, [skip], [mask] ) → table | nil
Same, but sweeps a box. mins and maxs are { x, y, z } tables.
trace.point_contents( x, y, z, [mask] ) → number
What’s at a point, as a bitfield of enums.contents. No ray, no filter — the cheap “am I inside something” test.
trace.bullet( target, x, y, z, [penetrate] ) → table
How much damage your currently held weapon would do to target at that point, walls included. This is the cheat’s own penetration maths, so it agrees with what the aimbot believes.

Draw a dot where you’re looking.

callbacks.add( "paint", function( )
    local me = entity.get_local_player( )

    local eye = me:get_origin( )
    eye[ 3 ] = eye[ 3 ] + 64

    local t = trace.line( eye[ 1 ], eye[ 2 ], eye[ 3 ],
                          eye[ 1 ] + 4096, eye[ 2 ], eye[ 3 ] )

Traces are not free. A handful per frame is nothing; a few hundred will cost you frames.

world

net

What the connection is actually doing: ticks, choke, latency.

net.server_tick( ) · net.client_tick( ) · net.delta_tick( )
The last tick the server told us about, our own clock, and the delta the last update was built against.
net.choked_commands( )
Commands built but not sent yet — the fake lag currently in flight. This is the engine’s count, the one the server will act on.
net.our_choke( ) · net.our_max_choke( )
What soggybot chose this tick, and its ceiling. Normally the same as net.choked_commands(); when they differ, the cheat has decided something the engine hasn’t acted on yet.
net.last_outgoing_command( ) · net.last_command_ack( )
The newest command we sent, and the newest the server has confirmed. The gap is what’s in flight.
net.latency( [flow] ) · net.avg_latency( [flow] )
Seconds, not milliseconds. flow defaults to enums.flow.outgoing, which is the half people mean by “ping”.
net.interp( )
The interpolation amount the cheat uses when deciding whether a backtrack record is still valid.
net.choked_packets( ) · net.sequence( )
Channel-level counters. sequence gives { out, in, out_ack }.
net.address( ) · net.is_loopback( )
Server address, and whether it’s a local server or a demo.
net.is_in_game( ) · net.is_connected( )
is_connected is already true while still loading.
net.client_tick() and globals.tickcount() normally agree. They only come apart while the ping reducer is running, which moves the game’s clock forward to read the newest snapshot early.
Every value here is read from the engine when you ask for it, so these are honest from paint and the net update events too — not just the move events.

cvar

Read and write game settings.

cvar.find( name ) → convar | nil
nil if there’s no such convar. Console commands (quit, clear…) are not convars and give nil too.
cvar.name
Shorthand for the same thing. cvar.sv_gravity:get_float().

reading

c:get_int( ) · get_float( ) · get_bool( ) · get_string( )
The value, however you want it.
c:get_flags( ) · c:get_help( ) · c:get_default( )
Flags are a bitfield — see enums.fcvar.
c:get_min( ) · c:get_max( )
nil when the convar has no bound on that side.
c:name( ) · c:valid( )
Its name, and whether it still resolves.

writing

c:set( value ) → bool
Takes a number, a string or a boolean. Returns false and says why in console if the write was refused.

what gets refused, and why

kindwhat happens
Replicated convars
sv_gravity, sv_maxunlag, weapon_recoil_scale…		Refused. The server owns these. Writing one changes your copy only, so your movement and the aimbot’s maths quietly stop matching the server — until it resends and your change vanishes.
Convars soggybot drives
cl_interp, cl_predict, fog_*, name…		Refused. Something re-stamps these every frame, or the cheat reads them and assumes it’s the only writer. You’d be fighting it and losing.
Everything else
fps_max, viewmodel_*, crosshair…		Allowed.

example

Read a value the cheat also cares about.

local g = cvar.find( "sv_gravity" )
if g then
    print( "gravity is", g:get_float( ) )
end

-- shorthand, same thing
print( cvar.fps_max:get_int( ) )
The cvar.name shorthand is sharper than it looks. A typo gives you nil, and calling a method on nil raises — which unloads your whole script. cvar.find() lets you check first.
Lookups are remembered after the first one, so calling cvar.find every frame is fine.

playerlist

Who’s on the server, and who the aimbot should leave alone. The same list the plist tab shows.

playerlist.get_all( [enemies_only] ) → table
Everyone on the server, as an array.
playerlist.get( index ) → table | nil
One player by entity index.
playerlist.is_whitelisted( index ) → bool
Whether the aimbot is ignoring them.
playerlist.set_whitelist( index, bool ) · playerlist.toggle_whitelist( index )
Both return the resulting state. Saved to disk straight away.
playerlist.saved( ) → table
The stored whitelist, including people who aren’t here right now. Each entry has steamid and the last name we saw them use.
playerlist.forget( steamid ) · playerlist.clear( )
Drop one stored entry, or all of them.

a player entry

keymeaning
index · nameEntity index and current name.
playerThe entity, for everything else.
steamidA string, always — see the warning below.
enemy · botWhether they’re on the other team, and whether they’re a bot.
alive · dormantdormant means the server has stopped sending us their updates.
whitelistedWhether the aimbot is ignoring them.

example

Ignore everyone who is winning.

callbacks.add( "player_death", function( e )
    local victim = e:get_player( "userid" )
    if not victim then return end

    for _, p in ipairs( playerlist.get_all( true ) ) do
        if p.player:get_health( ) > 90 then
            playerlist.set_whitelist( p.index, true )
        end
    end
end )
Steam IDs are strings, not numbers. They’re bigger than a Lua number can hold exactly, so passing one around as a number silently rounds it and you end up whitelisting the wrong person.
Whitelisting stops the aimbot targeting them. Nothing else changes. ESP still draws them, the resolver still works on them, and the anti aim still treats them as someone who can see you — which is what you want, because they can.
Bots are only whitelisted for the current session. They have no Steam account to remember them by.

ffi

Direct memory access. Turn on allow unsafe scripts in the scripts tab first.

local ffi = require( "ffi" )

local addr = me:get_prop_address( "m_flFlashDuration" )
ffi.cast( "float*", addr )[ 0 ] = 0
ffi can do anything the cheat can, including crash the game. Only turn it on for scripts you trust. It also bypasses every restriction listed elsewhere in these docs.
get_prop_address and entity.get_offset are there so you don’t have to look offsets up yourself, and so they keep working after a game update. Hardcode one if you’d rather, or if the prop isn’t something they can resolve.

reference

gotchas

predicted values depend on when you read them
get_inaccuracy, get_spread, get_mode and can_fire are predicted. In pre_move they’re a tick behind; in in_move they’re current.
objects only live inside their callback
cmd, shot, the esp context and game events all stop working once the callback returns. Copy out what you need.
one set_callback per control
Calling set_callback twice on the same control replaces the first one.
drawing only works in paint and player_esp
Except box3d and capsule3d, which you call once with a duration.
errors unload your script
The error prints to console. This stops a broken script spamming every frame.
column 0 vs column 1
Without a subtab, column 0 is taken by the script list — use column 1. With a subtab, both are yours.
old handles are safe
A handle to something that no longer exists returns nil. It won’t crash.

slowwalk on its own page

local page  = ui.subtab( "scripts", "slowwalk" )
local key   = ui.hotkey( "scripts", 0, "slowwalk key" )
local speed = ui.slider( "scripts", 0, "speed", 10, 250, 80 )

key:set_subtab( page )
speed:set_subtab( page )

callbacks.add( "pre_move", function( cmd )
    if not key:get( ) then return end

    local want = speed:get( )
    local f, s = cmd:get_forwardmove( ), cmd:get_sidemove( )
    local len  = math.sqrt( f * f + s * s )

    if len > want then
        cmd:set_forwardmove( f / len * want )
        cmd:set_sidemove( s / len * want )
    end
end )
