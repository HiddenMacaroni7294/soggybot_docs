start

overview

Put .lua files in Documents\<user>\scripts\ and load them from the scripts tab.

Every script runs in its own sandbox, so scripts can't break each other. If a script errors it gets unloaded and the error is printed to console.

-- a minimal script
local enabled = ui.checkbox( "scripts", 1, "my script", true )

callbacks.add( "paint", function( )
    if not ui.get( enabled ) then return end
    render.text( 10, 10, 255, 178, 0, 255, "hello" )
end )
Where things live. ui makes menu controls, render draws, entity reads the game, callbacks hooks events. Everything returns nil rather than erroring when something isn't available.

callbacks

Hook an event and your function runs whenever it fires.

callbacks.add( event, fn )
Register a handler. You can add more than one per event.
callbacks.remove( event )
Remove every handler your script added for that event.

post_movecmdLast chance to change the cmd.

paint

callbacks.add( "paint", function( )
    local w, h = render.screen_size( )
    render.text( w - 120, 10, 255, 178, 0, 255, "soggybot" )
end )

pre_move

-- auto-crouch while in the air
callbacks.add( "pre_move", function( cmd )
    if cmd:has_button( buttons.IN_JUMP ) then
        cmd:add_button( buttons.IN_DUCK )
    end
end )

in_move

-- stop moving when our accuracy is bad
callbacks.add( "in_move", function( cmd )
    local me = entity.get_local_player( )
    local w  = me and me:get_weapon( )
    if not w then return end

    local inacc = w:get_inaccuracy( )
    if inacc and inacc > 0.05 then
        cmd:set_forwardmove( 0 )
        cmd:set_sidemove( 0 )
    end
end )

post_move

-- count the ticks we actually sent
local sent = 0

callbacks.add( "post_move", function( cmd )
    if cmd:get_send_packet( ) then
        sent = sent + 1
    end
end )
Order matters for predicted values. get_inaccuracy, get_spread, get_mode and can_fire are predicted, so when you read them changes what you get:

· pre_move — one tick behind
· in_move — current, and what the aimbot is about to act on
· post_move — already updated for next tick

Read them in in_move unless you specifically want otherwise.
in_move does not fire while the doubletap key is held. pre_move and post_move still do.

examples

Complete scripts. Save any of these as a .lua file and load it.

watermark with a toggle

local on   = ui.checkbox( "scripts", 1, "watermark", true )
local col  = ui.color_picker( "scripts", 1, "colour", 255, 178, 0, 255 )
local font = render.create_font( "Verdana", 14, 500 )

callbacks.add( "paint", function( )
    if not ui.get( on ) then return end

    local c    = ui.get( col )
    local text = string.format( "soggybot | %d fps",
                    1 / math.max( globals.frametime( ), 0.0001 ) )

    local tw, th = font:get_size( text )
    local sw     = render.screen_size( )
    local x, y  = sw - tw - 14, 10

    render.rect_filled( x - 5, y - 3, tw + 10, th + 6, 0, 0, 0, 150 )
    font:text( x, y, c[1], c[2], c[3], c[4], text )
end )

enemy health text

local on = ui.checkbox( "scripts", 1, "health esp", true )

callbacks.add( "paint", function( )
    if not ui.get( on ) then return end

    for _, p in ipairs( entity.get_players( true ) ) do
        if not p:is_dormant( ) then
            local o = p:get_origin( )
            local s = render.world_to_screen( o[1], o[2], o[3] )

            if s then
                local hp = p:get_health( )
                render.text( s[1], s[2],
                    255 - hp * 2, hp * 2, 40, 255, tostring( hp ) )
            end
        end
    end
end )

its own subtab, with a hotkey

local page  = ui.subtab( "scripts", "slowwalk" )
local key   = ui.hotkey( "scripts", 0, "slowwalk key" )
local speed = ui.slider( "scripts", 0, "speed", 10, 250, 80 )

ui.set_subtab( key, page )
ui.set_subtab( speed, page )

callbacks.add( "pre_move", function( cmd )
    if not ui.get( key ) then return end

    local want = ui.get( speed )
    local f, s = cmd:get_forwardmove( ), cmd:get_sidemove( )
    local len  = math.sqrt( f * f + s * s )

    if len > want then
        cmd:set_forwardmove( f / len * want )
        cmd:set_sidemove( s / len * want )
    end
end )

reacting to a menu change

local mode  = ui.combobox( "scripts", 1, "mode", "off", "low", "high" )
local power = ui.slider( "scripts", 1, "power", 0, 100, 50 )

-- hide the slider unless a mode is picked
ui.set_callback( mode, function( )
    ui.set_visible( power, ui.get( mode ) ~= 0 )
end )

Creators take (tab, column, name, …) and give you a handle. column is 0 or 1.

ui.button( "scripts", 1, "do it", function( )
    print( ui.get( b ) )
end )

If an entity stops existing, its functions return nil instead of crashing. You don't need to re-fetch it every frame, but it's cheap if you do.

entities

netprops

Read and write networked properties by name.

local flash = me:get_prop( "m_flFlashDuration" )
local off   = entity.get_offset( "DT_BasePlayer", "m_vecOrigin" )
e:get_prop( name )
Returns the value, or nil if that prop doesn't exist on this entity.
e:set_prop( name, value ) restricted
Returns true on success. Some props are blocked — see below.
e:get_prop_address( name ) · e:address( )
Memory address, for use with ffi.
entity.get_offset( table, prop ) → number | nil
Offset without needing an entity.
set_prop blocksreason
other playersThe server overwrites it immediately, and it confuses the cheat's own tracking.
animation propsThe cheat manages these itself.
predicted propsThey get reset every prediction, so the write wouldn't stick.
A blocked write prints the reason to console, so you'll know why nothing happened. Use ffi if you need to do it anyway.

weapon data

w:get_wpn_data() returns a table of everything the game knows about that weapon. These never change, so read once and keep it.

local d = w:get_wpn_data( )
print( d.name, d.damage, d.cycletime )
groupfields
timingcycletime, cycletime_alt, time_to_idle
damagedamage, armor_ratio, bullets, penetration, range, range_modifier
accuracyspread, inaccuracy_stand, _crouch, _move, _jump, _jump_initial, _land, _ladder, _fire, _reload
recoveryrecovery_time_stand, _crouch, their _final, recovery_transition_start_bullet, _end_bullet
recoilrecoil_angle, recoil_magnitude, their variances, recoil_seed

Most fields have an _alt version — that's the value when the weapon is scoped, silenced or in burst mode. Use w:get_mode() to know which applies.
cycletime is how fast the weapon shoots. recovery_time_* is how fast accuracy comes back after shooting. Different things.

objects

cmd

The move commands hand you a cmd. It's how you change what gets sent to the server.

callbacks.add( "pre_move", function( cmd )
    cmd:set_forwardmove( 250 )
    cmd:strip_button( buttons.IN_JUMP )
end )
cmd:get_yaw( ) · cmd:set_yaw( v )
Also pitch and roll.
cmd:get_forwardmove( ) · cmd:set_forwardmove( v )
Also sidemove and upmove.
cmd:get_send_packet( ) · cmd:set_send_packet( bool )
Whether this tick is sent to the server.
cmd:get_weaponselect( ) · cmd:set_weaponselect( v )
Weapon switch.
cmd:add_button( bit ) · cmd:strip_button( bit ) · cmd:has_button( bit )
Add, remove, or test a button. See buttons.
cmd:get_buttons( ) · cmd:get_command_number( ) · cmd:get_tick( ) · cmd:get_random_seed( ) read only
Changing these would desync you from the server.
IN_ATTACK is handled by the cheat. You can't remove it — the aimbot already decided. You can add it, but only when client.can_fire() is true. Both calls return false if the attack bit was ignored.
Only use cmd inside the callback that gave it to you. Don't save it in a variable for later.

misc

ffi

Direct memory access. Turn on allow unsafe scripts in the scripts tab first.

local ffi = require( "ffi" )

local addr = me:get_prop_address( "m_flFlashDuration" )
ffi.cast( "float*", addr )[ 0 ] = 0
ffi can do anything the cheat can, including crash the game. Only turn it on for scripts you trust. It also bypasses every restriction listed elsewhere in these docs.
get_prop_address and entity.get_offset exist so you don't have to look offsets up yourself, and so they keep working after a game update. Hardcode one if you'd rather, or if the prop isn't something they can resolve.

reference

gotchas

predicted values depend on when you read them
get_inaccuracy, get_spread, get_mode and can_fire are predicted. In pre_move they're a tick behind; in in_move they're current.
one set_callback per control
Calling ui.set_callback twice on the same handle replaces the first one.
drawing only works in paint
Except box3d and capsule3d, which you call once with a duration.
errors unload your script
The error prints to console. This stops a broken script spamming every frame.
column 0 vs column 1
Without a subtab, column 0 is taken by the script list — use column 1. With a subtab, both are yours.
old handles are safe
A handle to something that no longer exists returns nil. It won't crash.
